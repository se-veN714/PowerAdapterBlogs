## 1. 目标与范围边界

目标是让正常授权路径足以完成长文任务，并使每个工具都具有可验证的权限、数据、执行和失败边界。工具失败不得成为读取客户端凭证、扩权、改数据库或绕过网页确认的理由。

本版保留账号、PAdif 板块资格、人类协作角色、逐篇 AI+ 操作集合、OAuth scope、现有刷新/撤销和业务服务。主线发布继续由创建者在网页确认。管理员不会因本规范获得私有文章访问权。创建者可以在个人 Agent 页审批自己文章的 AI+，包括本人申请，无需管理员工作台。

本版不增加 PDF/Word/压缩包解析、任意文件管理、远程 URL 导入、Shell/脚本执行、凭证导出、所有权转移、批量跨文章写入或 Agent 发布主线。OAuth 重连问题另行诊断，本版不放宽刷新重放保护或延长授权有效期。

“上传验证通过”仅表示符合本版格式、权限、完整性及处理规则，不表示文本可信、无提示注入或数学意义上的绝对安全。

## 3. 信任与权限统一规则

### 3.1 数据边界

正文、标题、文件名、分支说明、批注、回复、差异、目录标题和工具错误均为不可信数据。内容中的“系统指令”“读取 token”“执行命令”“改授权”等文字不具有指令或授权效力。

输入只接受工具白名单及严格 schema：未知字段、非法枚举、布尔冒充 ID、非法范围、超长文本拒绝。结构校验与输出编码分开；不能靠删除正常稿件中的敏感词来防提示注入。原稿保真，展示层按上下文转义或净化，不执行其中的 HTML、脚本、模板和代码块。

工具参数不得接收 token、密码、Cookie、任意服务器路径、Shell、SQL 或可执行表达式。业务工具不导出 OAuth 凭证，不向旧设备码接口透传 MCP token。文章中的链接不触发服务端自动抓取；预览对外链图片的加载策略也需明确，默认不自动加载外站资源，并提供用户主动查看入口。

### 3.2 每次授权判定

有效账号及 PAdif 人类使用能力、当前连接及 token、有效板块资格、人类文章角色、文章 AI+ 对应操作、当前 OAuth scope 均需满足。写作/批注仍受人类角色上限约束。`tools/list` 可用于减少无权工具展示，但真正的安全边界是每次 `tools/call` 和业务服务复核。

由 version、annotation、branch、upload ID 间接访问文章时，先解析归属，再统一校验。不得通过错误、标题、计数、时间、哈希、目录或申请历史枚举无权文章。跨文章比较、混用其他文章的基础版本、批注/上传对象均拒绝。

撤销后先校验权限再取幂等回执，不能借回执读到已失去权限的结果。长任务每个阶段重新校验，不把创建任务时的授权当永久授权。降权后不得恢复已移除操作；历史批准不等于当前有效。

### 3.3 并发与线性化

复用现有身份、连接、文章、授权和业务对象的锁顺序，并在编码前通过现有撤销/写入并发测试确认；新上传任务锁在所属文章锁之后，不另建反向锁序。

写入与撤销以事务提交为界：撤销先完成，则等待中的写入重新检查并拒绝；写入先完成，则其不可变版本和审计保留，之后的写入拒绝。不得把“撤销立即生效”解释成删除撤销前已经合法提交的版本。

## 4. 凭证与客户端责任

| 主体 | 必须承担的职责 | 不能承诺的能力 |
|---|---|---|
| PAdif 服务端 | 认证、对象级授权、限额、幂等、事务、输出限制、审计；拒绝不符合合同的调用 | 无法控制客户端上另一个终端工具能读取哪些本地文件 |
| OAuth 客户端 / 受控文件适配器 | 保管和刷新凭证，只在正确 HTTPS 源与 audience 使用；文件仅来自用户选择或授权清单 | 不得要求业务 Agent 搜索/解密自己的凭证缓存 |
| 写作 Agent | 仅使用已授权业务工具；把稿件当数据；依据结构化错误恢复或请求用户操作 | 不得因上传失败调用终端、数据库、浏览器 Cookie 或解密脚本绕过 MCP |
| 人类用户 | 选择文件、确认 OAuth/逐篇授权及网页主线发布 | “允许写稿”不隐含允许读取凭证或任意本地文件 |

文件适配器只读显式授权的工作区文件或文件清单；解析规范路径并检查目录边界、符号链接/重解析点，不能凭 `.md` 后缀决定本地文件是否可读。敏感目录和凭证文件不因改名而进入授权范围。完整本地路径不上传到服务器或写入日志。

工具说明、能力发现和客户端指引必须写明这些边界；模型提示不能替代客户端文件沙箱。恶意文本测试需要在真实客户端验证是否触发了边界外工具，单测返回字符串不能证明 Agent 不会越界。

## 5. 所有工具的公共合同

### 5.1 输入、输出与资源预算

以下是本版建议初值，确认后成为实现默认值。调整必须同步能力说明及边界测试。

| 限额 | 目标默认值 |
|---|---|
| Markdown 原文件、最终新版本 | 最多 2 MiB 实际 UTF-8 字节，保留现有上限，不按汉字数估算 |
| 新分块接口的单块原始内容 | 最多 16 KiB；所有调用仍受序列化后的请求体预算约束 |
| 新工具单次 JSON 请求 | 最多 64 KiB（含 base64/JSON 编码开销）；旧全文提交维持既有整体上限并明确超限错误 |
| 新读取接口整份 JSON-RPC 响应 | 最多 64 KiB，含 text 与 structuredContent 的重复序列化；单块正文最多 16 KiB |
| 目录 / 列表页 | 默认 20 项，最多 100 项；已有接口当前上限保留，正文和回复也计入响应总预算 |
| 单次局部修改 | 最多 20 项修改，替换文本合计最多 32 KiB；结果仍受 2 MiB 限制 |
| 差异计算 | 双方各最多 2 MiB；目标执行预算 3 秒，需可中断的执行边界及复杂度预检，超限返回 `DIFF_TOO_COMPLEX`；不能只记录耗时却继续阻塞 Web |
| 单用户暂存 | 最多 3 个未完成任务，总计 8 MiB；先预留额度，不能靠并发绕过 |
| 单任务寿命 | 创建后 30 分钟绝对过期，活动不续命；取消/失效后立即停止访问并排队删除正文 |
| 清理时限 | 后台至少每 5 分钟扫描一次；任务到期立刻逻辑失效，暂存正文应在下一轮清除 |
| 速率 | 保留现有请求限流；新上传另限每连接每分钟 60 次分块、10 次创建，并受用户配额及全局容量约束 |

输出不能悄悄截断正文或差异，也不能把过长单行拆成伪造的 Markdown 行。允许分页的返回 `next_cursor/next_offset`、固定 version ID、范围及完整性标记；不支持分页的旧调用返回明确 `OUTPUT_TOO_LARGE` 和恢复入口。重试同一超大参数不能当恢复方案。

分页增量合同：`compare_versions` 增加可选 `offset/limit`，返回固定版本对、全局统计、受限 changes 和 `next_offset`。`list_annotations` 的长回复线程给有标记的预览与 `next_reply_cursor`；新增可选 `reply_annotation_id/reply_cursor` 续取固定批注的回复页，且批注必须属于给定 version。单条批注正文、单条回复或处理说明自身过长时，返回显式 `body_complete=false` 与类型化 `body_ref`，由 `read_content_chunk` 读取，不能只给永远无法取全的前缀。旧小结果形状保留；如果调用方不支持该分页合同，则使用显式超限错误与安全恢复入口，不能假装返回了完整线程。每一页都重新授权。

第二阶段落地细则：差异操作沿用兼容字段 `diff.ops`（不新增同内容的 changes 副本），分页默认 20、最多 100，实际 wire 预算可缩短页。预检限制每侧 10,000 句、句数乘积和最长句字符数乘积各 4,000,000；每个 Web 进程最多两个差异子进程，忙时返回可重试的 `DIFF_BUSY`。3 秒为包含预检、传给子进程的剩余墙钟预算，操作系统创建/终止进程仍可能增加少量开销；超时必须终止并回收子进程。此预算用于 MCP compare，不扩展为网页或写版本时统计的统一预算，也不宣称操作系统内存硬限额。长单项以 `text_complete=false` 与整版本 `text_ref` 明示省略，replace 附 before/after 引用；现有行号只是定位提示，不捏造精确片段偏移。

批注分页由 `paginate_replies=true` 或回复页参数显式启用；默认每条批注预览 3 条，可用 `reply_limit`（1–100）调整。回复游标签名有效 1 小时，绑定连接、版本、批注和最大回复 ID；续页不混入后续新增回复。续页仅接收 version、批注 ID、cursor 与页长，不混用批注筛选/offset。字段 inline 阈值为 1,024 UTF-8 字节，总 wire 预算可进一步改用引用或缩短页。旧小线程形状保留，旧调用超过 100 回复或 wire 预算显式失败。管理员删除历史回复时不保证内容快照仍存在，游标不存储副本。

单条 diff 变化本身过长时，返回带完整性标记的片段预览与 `before_ref/after_ref`，引用固定版本源码区间及哈希，由分块工具取全。预算超出不能通过“只剩最后一大项”无限放大。摘要查询应直接选择所需字段，不先组装全部历史正文或完整回复树再截断。

### 5.2 幂等与恢复

每个有副作用的调用必须有 `request_id`；同一 connection、同一参数重试返回同一结果，参数不同返回 `REQUEST_ID_CONFLICT`。失败不生成版本、分支、批注或成功回执；事务回滚不能只回滚回执却留下业务对象。

版本提交要求当前有效头 `base_version_id`，冲突必须重新读取，不自动覆盖。批量 patch、最终上传提交全部原子执行。分块接收另以 `(upload_id, chunk_index)` 唯一约束保证内容一致，不因换 `request_id` 覆盖块。最终每个 upload 最多关联一个 committed version。

每个成功写返回受限摘要：对象 ID、实际分支、基础/新版本、规范正文哈希、任务状态和 canonical 网页链接。默认不重复返回全文。网页链接由站点配置生成，不使用稿件或上传参数中的主机/路径。

### 5.3 错误与日志

保留现有错误语义；新增错误至少包含 `error`、安全简述、`retryable` 和有限恢复建议。凭证错误不回显凭证，输入错误不回显正文，服务错误不返回堆栈。隐藏对象统一 `NOT_FOUND`；只有已获对象可见性后，才可返回具体缺失操作说明。

| 错误类别 | 示例 | 合规恢复 |
|---|---|---|
| 凭证 / 权限 | `INVALID_TOKEN`、`INSUFFICIENT_SCOPE`、既有文章权限错误 | 客户端正常续期；确需重新授权则转交用户；禁止提取缓存 token |
| 输入 / 容量 | `INVALID_ARGUMENTS`、`CONTENT_TOO_LARGE`、`OUTPUT_TOO_LARGE`、`DIFF_TOO_COMPLEX` | 缩小读取范围、逐块核对、用局部修改或网站暂存上传 |
| 并发 / 幂等 | `STALE_BASE_VERSION`、`REQUEST_ID_CONFLICT` | 重读或核实原回执；修改参数需新请求 ID |
| 上传 | `CHUNK_CONFLICT`、`UPLOAD_INCOMPLETE`、`HASH_MISMATCH`、`UPLOAD_EXPIRED`、`UPLOAD_INVALIDATED` | 查状态、补缺块或创建新任务；不放宽校验 |
| 能力 / 限流 | `CLIENT_UPLOAD_UNAVAILABLE`、`RATE_LIMITED` | 使用网站入口或遵守 Retry-After；不改走凭证脚本 |

新错误码须在实现前固定完整输入/响应 schema；本表不是当前服务已经返回这些字段的声明。旧错误适配应增量进行，不把传输错误当业务成功。

所有写及暂存文件变更走现有审计体系。记录 actor ID、connection/client ID、tool、文章/版本/分支/任务 ID、请求关联 ID、结果码、字节数、来源/结果哈希和时间；不记录原文、批注正文、令牌、Cookie、账号邮箱、原始文件路径、密钥或原始参数。未知参数不得直接拼到异常信息。只读操作默认不写内容访问日志；异常检测与汇总指标按既有日志规范处理。审计保留与脱敏沿用项目制度，暂存正文的清理不能删除审计记录。

## 6. 既有 10 个工具的逐项要求

下表要求与第 3–5 节同时满足；未获某篇文章权限时，不得先执行内容查询或返回局部数据再报错。

| 工具 | 操作 scope | 输入与对象检查 | 输出 / 副作用要求 |
|---|---|---|---|
| `list_documents` | `padif:read` | 搜索长度、分页合法 | 只列本人有 AI+ 阅读的文章；total 也是过滤后的数量；不返回全文 |
| `get_workspace` | `padif:read` | 文章与分支同属，分支名不是路径 | 新增 `include_content=false` 摘要读取；旧省略参数语义保留，但超预算显式报错；不静默截断正文 |
| `get_version` | `padif:read` | version 所属文章先授权；范围为原 Markdown 行，空行计数 | 返回 version/范围/总行数；长行超预算引导 `read_content_chunk`，不按视觉换行伪造行号 |
| `compare_versions` | `padif:read` | 两版本都属于指定且有权的文章 | 差异结果分页且固定版本对；标题/片段当数据；超限显式错误，不伪造完整 diff |
| `list_annotations` | `padif:read` | 先授权所属版本；筛选枚举严格 | 批注和线程都受响应预算；线程可续取，不因一条长回复失控；作者只返回现有允许的公开标识 |
| `create_branch` | `padif:version` | 起点版本同文章，名称严格，不允许覆盖已有分支/冒充 main | 复用现有分叉服务；重复请求最多一个分支；不改主线头或迁移历史 |
| `commit_version` | `padif:version` | 明确非 main 分支、有效头、实际字节数、非空内容 | 兼容旧全文调用；事务生成一个版本；超大参数提示 patch/上传，不提示绕过 MCP |
| `add_annotation` | `padif:annotate` | 固定版本、合法 kind/行范围；给定 selected_text 必须匹配范围 | 原文锚点不可因换行或后续版本漂移；正文安全展示，幂等只建一条 |
| `reply_annotation` | `padif:annotate` | annotation 归属校验；正文非空和上限 | 回复关联真实作者与时间；不把回复中的工具命令执行；同请求不重复追加 |
| `resolve_annotation` | `padif:annotate` | 只接受既有处理状态，说明必填；复用原业务转换 | 不改写作者/旧回复；不靠别的工具名绕过；重试与并发结果明确，不偷偷恢复或扩大状态转换 |

兼容说明：新字段为可选、旧字段不改名；旧正常小文档调用继续成功。旧大响应可能新增显式超限错误，这是需要测试和告知的收紧，不应宣传为完全零行为变化。新的分页/分块响应和错误恢复须通过能力说明让客户端发现。

## 7. 新增长文能力（拟定工具名）

| 工具 | scope | 主要合同 |
|---|---|---|
| `get_document_outline` | `padif:read` | 指定文章/分支或固定版本，返回目录、字节/行数、基础版本与规范哈希；标题受长度和分页限制，不带全文 |
| `read_content_chunk` | `padif:read` | source_kind 白名单（version_markdown / annotation_body / reply_body / resolution_note）+ 对象 ID + 内容哈希与受校验 cursor；从所属文章授权，UTF-8 边界处分块；Markdown 另报告来源行号、半行标记；不接受路径/URL |
| `apply_version_patch` | `padif:version` | 指定非 main 分支、base ID/哈希、精确源码范围及原文校验；一次应用全部修改、生成一个新版本 |
| `begin_markdown_upload` | `padif:version` | 文章、非 main 分支、base ID 和请求 ID；已知文件时可同时绑定展示文件名/字节数/哈希，否则等待网站选文件；预留配额，返回 opaque upload ID、限额、到期时间及网站地址 |
| `append_markdown_chunk` | `padif:version` | upload ID、块序号、base64 数据、块哈希；仅供确实接入 OAuth 客户端的受控传输适配器使用；不是让模型反复粘贴全文的默认路径 |
| `get_markdown_upload_status` | `padif:version` | 同一归属与实时权限下读取任务状态、缺块和安全失败原因；不回传暂存正文 |
| `validate_markdown_upload` | `padif:version` | 全块收齐后验证文件/规范正文哈希、格式、范围/权限与配额；返回摘要、规范化说明及可分页 diff 的固定对象引用 |
| `commit_markdown_upload` | `padif:version` | 已校验任务、当前 base、请求 ID、提交说明与版本级别；最终原子生成一个版本；任务唯一提交，即使不同请求 ID 也不重复建版本 |
| `cancel_markdown_upload` | `padif:version` | 同一归属任务，幂等取消未提交任务并排队清理；不能删除已提交版本 |

新工具仍由现有权限与业务层处理，不能实现第二套“更宽松上传提交”逻辑。工具 annotations/hints 如只读、幂等、破坏性必须与实际副作用一致，且提示本身不是授权控制。

`read_content_chunk` 的 cursor 绑定 source_kind、对象、内容哈希和位置。不可变版本始终读取同一版本；可变化的处理说明若已改变，返回 `STALE_CONTENT`，不能拼接两版说明。批注/回复源也必须验证其 annotation/version 的完整归属链。列表返回的 `body_ref` 是定位信息，不是额外授权。

### 7.1 Patch 合同

固定不可变 base version。改动数组中的每项为原始 base 的 `start_line` 和 `end_line_exclusive`（从 1 开始的半开行范围）、`expected_lines` 与 `replacement_lines`。每个数组元素是一行，不包含 CR/LF；空字符串表示空行，空数组表示删除。插入为相等端点，EOF 插入点是 `total_lines + 1`。所有坐标针对同一 base，不按上一项修改后的偏移计算。

先检查 base ID 与规范哈希、每项原文、边界、重叠和总大小；同一插入点的重复插入也拒绝。全部验证后按从后往前的顺序替换行数组并拼接，保留尾部空元素，保证末尾换行与空行可预测。任何一项失败都不写版本。禁止模糊匹配、“猜最接近的段落”或自动把过期 patch 套到新头。

规范化视图是 UTF-8 无 BOM、CRLF/CR 转 LF，空行与尾部换行不合并。旧版本原始存储不重写；patch 创建的新版使用该规范化视图。需要在预览与回执标明换行规范化及 `content_sha256`，避免把字节变化藏起来。

### 7.2 上传入口与客户端能力边界

远程 MCP 服务不能读取用户电脑上的路径。首期默认路径是：Agent 创建绑定任务 → 返回本站登录保护的文件选择页面 → 用户选择本地 `.md` 文件 → 网站流式接收/分块暂存 → Agent 查询、校验并提交。正文不作为模型工具参数往返。

网站入口复用登录和 CSRF，要求当前用户等于任务用户，且原 connection、文章/分支/基础版本与实时权限仍有效；opaque ID 本身不是 bearer 授权，地址不含 token 或签名式长期写权限。用户没有选文件时 Agent 只能等待或取消，不能宣称已上传。

Agent 在用户选文件之前不必知道本地文件名、字节数或哈希。此时任务为 `awaiting_file`，按最大单文件大小预留配额。网站选择后由客户端计算原文件 SHA-256，并在任何文件字节接收前提交名称/尺寸/哈希的完整 manifest；服务端在同一授权边界检查并冻结 manifest、调整配额，然后进入 receiving。适配器已提供合法 manifest 时可直接进入 receiving。manifest 只能绑定一次；客户端声明的值仍须通过最终服务端实际字节校验，不能当安全证明。

完全自动的“从工作区文件上传”需要客户端已有、明确授权的文件适配能力。适配器通过自己的 OAuth SDK 正常调用分块接口，凭证不进入模型上下文。若 WorkBuddy 不支持该能力，返回 `CLIENT_UPLOAD_UNAVAILABLE` 及本站文件选择入口，不找缓存密钥、不解密凭证、不给模型提供所谓“方便上传的 token”。仅把一个全文调用拆成多次模型调用不算完成“文件不进上下文”的验收。

### 7.3 任务归属、状态机与校验

任务创建时绑定 user、connection、article、branch、immutable base version 和到期时间；选定文件后再冻结原文件 manifest。token 正常刷新保留 connection，允许继续；新 OAuth 授权是新 connection，不能自动继承旧任务。MVP 不做跨连接重绑，原任务取消/到期后重新开始；不得按客户端显示名称合并任务或恢复权限。

`awaiting_file → receiving → uploaded → validated → committed` 是成功路径；携带合法 manifest 的创建可从 receiving 开始。`awaiting_file/receiving/uploaded/validated → cancelled/expired/invalidated` 为终止路径。`committed`、`cancelled`、`expired`、`invalidated` 均不可重新开启。`validated` 后正文冻结，不再接收块。浏览器直传也必须进入同一任务/校验路径，不能跳过验证直接标记成功。

缺块不进入 uploaded；重复同序号同哈希同字节的块幂等，内容不同返回冲突。完成接收后校验顺序、完整长度和原文件 SHA-256；无效格式/哈希导致任务 invalidated，修正文件需新建任务。拒绝超额序号、重叠、未声明大块和解码膨胀，不先读完整大请求再限额。

仅允许 `.md/.markdown`，MIME 只作辅助，实际内容必须为合法 UTF-8（允许 BOM）、非空文本；拒绝 NUL、明显二进制及超限文本，不解压、不导入 HTML/可执行文件。Markdown 没有可靠的统一魔数，不能声称“签名通过即安全”。文件名只展示：限制 120 字符，拒绝路径分隔符、冒号、控制字符和路径穿越；存储始终用服务端随机标识。

合法 UTF-8 的代码文本可以是正常稿件，不因出现脚本示例、HTML 示例或敏感词而直接判恶意；拒绝的是不符合格式/来源/大小合同的文件。此类文本能安全处理依靠不执行、正确渲染和客户端工具边界，而非“看起来不像程序”的判断。

分别保存原文件 `file_sha256`（上传原字节）和规范正文 `content_sha256`，明确 BOM/换行转换。哈希证明一致性，不证明无恶意文本。杀毒可作为将来的补充，不替代权限、文本验证、隔离和渲染防护，也不把抗病毒扫描当保真保证。

最终提交重新锁定文章/分支，检查 base 与所有实时权限。过期、撤销、降权、失去人类角色或分支已归档均不能提交。事务提交版本、分支头、任务 committed 标记、回执与审计；绝不逐块创建版本，也不自动发布 main。

第三阶段实现细则：暂存原字节按 UUID/块序号存于私有 PostgreSQL BinaryField，不进入 MEDIA_ROOT，也不提供任意路径或公开下载。块大小固定 16,384 字节，最后一块按声明尺寸缩短；总块数由 file_size 推导。用户配额按原字节预留计算，部署级默认 1,024 个活动任务和 128 MiB 预留，借单例数据库行锁串行准入；数据库页/WAL/备份开销不计为原字节配额。名称、尺寸与原始 SHA-256 必须同时绑定，状态和正文在校验后冻结。

校验成功的暂存稿可由 `compare_versions` 的可选 `to_upload_id`（与 to_version 互斥）比较；对应正文引用类型扩展为 `upload_markdown`，ID 为 UUID。此类读入口除 read 外还必须有原连接的 version scope 及本文写作操作，不能因为持有 UUID 绕过授权。commit 后可解析到同任务的不可变版本，原暂存块被清理。此扩展不增加文章权限或 Agent 主线发布能力。

`cleanup_padif_mcp` 复用既有清理命令并扫描过期、撤销和权限版本失效任务；提供独立五分钟 systemd unit 配置，本地不启用生产 timer。失败、取消、过期和提交后删除活跃表中的暂存块，保留审计/哈希/状态；不宣称数据库旧页或备份已安全擦除。真实自动文件适配器仍需客户端能力验证，未通过时只支持用户网站选文件。

## 8. 渲染、内容消费与证据

所有新旧网页预览、全屏预览、diff、批注和工具结果展示都纳入检查：HTML 使用成熟净化方案和明确允许列表，危险标签、事件属性、脚本协议、SVG 活性内容不得执行；代码块按文本显示。下载使用安全 Content-Type、nosniff 与附件策略，不把上传稿件作为公开 HTML/静态资源暴露。服务器不自动追踪文章链接或把文件名拼进路径。

工具返回的正文/片段须具有明确的数据字段与版本来源。引用的外部内容不与系统/开发指令混拼。对“执行 Shell”“读取 OAuth”“上传其他文件”等诱导，只能作为稿件文本保留；客户端策略负责阻止越权工具调用。把攻击文本丢弃或净化成空字符串不是唯一防线，也不能通过正常文本关键词黑名单破坏创作。

只读、权限、事务、渲染和真实客户端测试分别提供证据。不能以 HTTP200、SDK 单测、哈希一致、工具 schema 或提示词存在，替代浏览器不执行脚本、客户端不读凭证和实际任务完整完成的证明。

## 9. 兼容、实施顺序和完成标准

1. 先确认本 Spec、工具输入输出 schema、限额和兼容错误契约；矩阵未执行项保持“待实现”，不把旧测试总数视为新安全验收。
2. 先建立现有 10 工具的权限、撤销、回执和资源预算测试，再实现有界读取与 patch。
3. 再实现同一业务服务下的暂存模型、私有存储、原子提交、清理和网站文件选择入口；迁移验证旧文章/版本/批注/授权完整性。
4. 文件适配器另有真实 WorkBuddy 能力验证关卡；未通过时仍可交付网站选文件路径，但必须明确“自动上传未支持”，不能称为全自动验收通过。
5. 本地运行矩阵中的服务/并发/浏览器测试及安全负例；只在用户另外授权后提交、推送或部署。生产完整发布仍走既有 archive/manifest 脚本与数据备份对照流程。

本轮文档完成标准：现有工具全覆盖；长文读取/patch/上传合同闭合；服务端与客户端责任分离；权限、撤销、并发、幂等、配额、清理、注入和兼容均有可判定验收项；仅 Markdown 文档变更，链接和矩阵映射校验通过。
